# 自动化测试指南

## 1. 测试目标

本项目采用分层测试，覆盖用户、新闻、收藏和浏览历史共 17 个后端接口。

测试必须满足以下安全约束：

- MySQL 只使用 `news_app_test`，不得连接或修改 `news_app`。
- Redis 只使用 DB 15，不得清理正式缓存。
- 每个测试结束后回滚数据库事务。
- 每个 API 测试前后清理 Redis DB 15。
- 测试数据必须可重复，不依赖当前时间或测试执行顺序。

## 2. 测试分层

| 层级 | 目录 | 验证内容 |
| --- | --- | --- |
| 单元测试 | `tests/unit` | 纯函数、响应结构、错误处理、缓存键 |
| 数据库集成测试 | `tests/integration` | ORM、事务、约束、排序、分页、用户隔离 |
| API 测试 | `tests/api` | 17 个接口、认证、参数、状态码、响应格式 |
| 端到端测试 | `tests/e2e` | 注册、登录、改密、阅读、收藏和历史完整旅程 |

依赖分层原则：能用单元测试稳定验证的逻辑不依赖数据库；需要验证真实 SQL、外键或唯一索引时使用集成测试；需要验证路由、认证和序列化时使用 API 测试。

## 3. 环境准备

创建本地测试配置文件 `.env.test.local`，内容参考 `.env.test.example`：

```dotenv
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=your_test_user
MYSQL_PASSWORD=your_test_password
```

该文件已被 `.gitignore` 忽略。不要在文档、测试代码或 URI 中保存真实密码。

测试代码会在导入应用之前设置以下变量：

```text
MYSQL_DATABASE=news_app_test
REDIS_DB=15
```

随后还会校验 `DATABASE_URL.database` 和 Redis 连接池中的 DB 编号。目标不匹配时，集成测试直接终止。

安装开发依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements-dev.txt
```

## 4. 运行测试

运行全部测试：

```powershell

```

按层级运行：


## 5. Arrange / Act / Assert

每测试只验证一个明确行为，并按照 AAA 组织：

```python
async def test_create_and_query_user(db_session: AsyncSession) -> None:
    # Arrange
    user = User(username="CRUD_USER", password=hash_password("secret"))

    # Act
    created = await create_user(db_session, user)
    found = await get_user_by_username(db_session, "CRUD_USER")

    # Assert
    assert found is not None
    assert found.id == created.id
```

- Arrange：构造最小、确定的输入和依赖。
- Act：只执行当前测试关心的行为。
- Assert：断言具体结果，不使用模糊的 `assert result`。

## 6. Fixture 的职责

公共 fixture 位于 `tests/conftest.py`。

| Fixture | 作用 |
| --- | --- |
| `prepared_test_database` | 创建测试库、重建表、清理 Redis，并在会话结束后关闭资源 |
| `db_session` | 为每个测试建立事务会话，测试结束后回滚 |
| `clean_redis` | 隔离测试前后清理 Redis DB 15 |
| `app_client` | 创建进程内 HTTP 客户端，并覆盖 `get_db` 依赖 |
| `catalog` | 提供固定分类、新闻和关联新闻数据 |
| `user_with_token` | 提供带有效令牌的测试用户 |

FastAPI 路由依赖的是 `get_db`，所以 API 测试必须覆盖 `get_db`，而不是数据库 engine。

## 7. 数据库隔离

测试库初始化会执行 `drop_all` 和 `create_all`，只在严格的 `news_app_test` 目标上允许。

每个测试的数据库会话加入外层事务，并启用保存点：

```python
transaction = await connection.begin()
session = AsyncSession(
    bind=connection,
    expire_on_commit=False,
    join_transaction_mode="create_savepoint",
)
```

应用接口可能调用 `commit()`，但保存点仍受外层事务控制。测试结束后执行 `rollback()`，从而清除该测试创建、修改和删除的数据。

事务回滚不会重置 `AUTO_INCREMENT`，因此测试不能断言新记录 ID 一定为 1。

## 8. Redis 隔离

MySQL 事务不能回滚 Redis 缓存，所以 API 测试在每个用例前后执行：

```python
await redis_client.flushdb()
```

只有确认 Redis 客户端连接的是 DB 15 后才会执行清理。

## 9. 测试数据原则

- 输入数据确定：固定用户名、固定新闻标题和固定发布时间。
- 排序需要稳定排序键，例如 `publish_time DESC, id DESC`。
- 只准备当前测试需要的字段。
- 同时覆盖成功和失败路径，例如重复用户名、过期令牌、不存在的记录。
- MySQL InnoDB 的 `TABLE_ROWS` 是估算值，验证数据是否清空必须使用 `COUNT(*)`。

## 10. API 覆盖

| 模块 | 数量 | 接口 |
| --- | --- | --- |
| 用户 | 5 | 注册、登录、信息、更新资料、修改密码 |
| 新闻 | 3 | 分类、列表、详情 |
| 收藏 | 5 | 检查、添加、取消、列表、清空 |
| 历史 | 4 | 添加、列表、删除、清空 |

API 测试同时验证：

- `Authorization` 请求头。
- camelCase 响应字段，例如 `userInfo`、`categoryId`、`favoriteTime`。
- HTTP 状态码和统一响应包络。
- 分页字段 `total`、`hasMore`。
- 写操作后的缓存失效。

## 11. HTTP 手工测试

`toutiao_backend/test_main.http` 包含全部 17 个接口请求。先启动服务：

```powershell
.\.venv\Scripts\python.exe -m uvicorn toutiao_backend.main:app --reload
```

然后在 IDE 的 HTTP Client 中按顺序执行请求。文件会自动：

- 从注册或登录响应提取 `token`。
- 从分类响应提取 `categoryId`。
- 从新闻列表响应提取 `newsId`。
- 从历史添加响应提取 `historyId`。

## 12. 常见问题

`news_app_test` 不存在：

使用具有建库、建表权限的测试账号运行集成测试。不要为了测试给正式库账号扩大权限。

数据库拒绝连接：

检查 `.env.test.local` 中的主机、端口、用户名和密码。不要把凭据写入测试代码。

Redis 无法连接：

确认 Redis 运行在 `localhost:6379`，并允许连接 DB 15。

测试单独运行通过、组合运行失败：

优先检查数据库事务是否回滚、Redis 是否清理、测试是否依赖固定 ID 或执行顺序。

表统计显示有数据但查询为空：

`information_schema.TABLES.TABLE_ROWS` 是 InnoDB 估算值，使用 `SELECT COUNT(*)` 获取准确行数。
