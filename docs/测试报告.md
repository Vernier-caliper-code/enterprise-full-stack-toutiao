- 测试只使用 `news_app_test`，不会使用 `news_app`。
- 每个数据库测试使用外层事务和保存点，测试结束统一回滚。

- 新闻发布时间固定，避免分页排序受当前时间影响。
- 不依赖自增 ID 等于固定值，不依赖测试执行顺序。
- 通过 `COUNT(*)` 验证测试数据已清理，不使用 InnoDB 的估算行数。

## 7. 关键业务验证

### 用户管理

- 新用户注册成功并返回令牌和默认资料。
- 重复用户名注册返回 400。
- 正确密码登录成功，错误密码登录返回 401。
- 缺失令牌和无效令牌返回 401。
- 用户资料更新后能够从数据库读回。
- 修改密码后新密码可登录，旧密码不可登录。

### 新闻浏览

- 分类按 `sort_order` 排序。
- 新闻列表按分类过滤、分页并正确计算 `total` 和 `hasMore`。
- 新闻详情返回关联新闻，并正确增加浏览量。
- 请求不存在的新闻返回 404。
- 新闻和分类数据在测试之间正确回滚。

### 收藏管理

- 收藏检查在认证后返回正确状态。
- 重复添加同一收藏保持幂等，不产生重复记录。
- 取消收藏只删除指定新闻。
- 收藏列表分页和 camelCase 时间字段正确。
- 清空收藏只影响当前用户。

### 浏览历史

- 添加历史后缓存列表失效并返回新记录。
- 历史列表按浏览时间倒序分页。
- 删除历史后再次删除返回 404。
- 清空历史只影响当前用户。

### 完整用户旅程

注册用户后依次完成资料更新、密码修改、重新登录、浏览分类和新闻详情、收藏、查看收藏、记录历史、删除和清理操作，全部通过。

## 8. 未覆盖范围与剩余风险

以下内容尚未纳入本轮自动化测试，不能据此认定生产环境没有风险：

- 并发请求、数据库连接池耗尽和缓存击穿。
- 真实网络环境下的超时、重试和 Redis 不可用。
- 大规模数据和慢查询性能。
- 浏览器前端、跨域、安全头和生产部署配置。
- 密码复杂度、用户名长度、手机号格式等业务规则的充分边界测试。
- 数据库迁移、历史数据兼容和备份恢复。
- 安全扫描、依赖漏洞扫描和渗透测试。
- 第三方服务可用性和生产监控告警。

当前注册和登录请求模型对空字符串、超长用户名和弱密码的行为主要依赖现有模型约束，建议后续补充明确的业务校验规则和边界测试。

## 9. 缺陷与建议

### 本轮缺陷

本轮测试执行结果中没有失败用例，未记录阻塞级或严重级缺陷。

### 改进建议

1. 增加 404、401、422 和重复操作的接口契约测试。
2. 为用户名、密码、手机号增加明确边界规则和对应测试。
3. 增加并发收藏、并发登录和缓存失效竞态测试。
4. 在 CI 中运行单元、集成和 API 测试，并为集成测试提供隔离数据库。
5. 增加 `ruff`、类型检查和依赖安全扫描。
6. 对核心查询补充大数据量性能基线和慢查询监控。
