AI掘金头条新闻系统 - 非功能测试报告

生成日期：2026-11-01。测试环境：Windows、Python 3.12.7、MySQL 8、Redis 7、Chromium。

总体判定

不通过。性能基线通过，但安全、故障恢复、限流和移动端可访问性存在阻断项。

性能基线

20 VU，80/20 读写混合，三次 60 秒运行取中位数。请求总数 22776，失败 0。

阻断缺陷

  1. P0 密钥泄露：构建产物包含疑似真实 DeepSeek API Key；该值同时出现在 Git 跟踪的环境示例文件中。报告不展示密钥值，必须轮换密钥并移除前端直连。
  2. P1 Redis 故障未降级：Redis 不可达时，公共读和带缓存失效的历史写入超过 10 秒仍未返回。
  3. P1 数据库故障返回 500：MySQL 不可达时接口未在 5 秒内返回统一 503，而是 500。
  4. P1 无登录限流：连续失败登录没有返回 429 或 Retry-After。
  5. P1 超大请求未被拒绝：300 KB 昵称请求进入数据库层，触发 DataError 和 500。
  6. P1 并发收藏竞态：20 个并发重复收藏触发唯一键冲突，恢复分支抛出 MissingGreenlet，部分请求返回 500（以 non-strict xfail 保留为已知缺陷探针）。
  7. P1 安全响应头缺失：缺少 X-Content-Type-Options、X-Frame-Options 和 Referrer-Policy。
  8. P1 axe 严重违规：首页存在 aria-required-children critical 级违规及多处文本对比度 serious 级违规。

风险项

  • 历史列表一次性读取热用户全部 10,000 条记录并 filesort，实测查询约 75.8 ms；数据增长后会线性恶化。
  • 前端构建的 JS gzip 总量约 161.2 KiB；无显式体积门禁。
  • Python 与 npm 已知依赖漏洞均为 0，Bandit 高危为 0，未发现 SQL 注入导致的 500。

通过项

  • 50 个并发新闻详情请求浏览量准确增加 50。
  • 并发登录返回不同令牌，不同用户历史数据未串读。
  • 375/390/440px 移动端无横向滚动；完整注册、详情、收藏和历史旅程通过。
  • 现有 42 个功能回归测试保持通过。
