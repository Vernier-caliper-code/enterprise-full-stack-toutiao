## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 项目名称 | AI 掘金头条移动端前端 |
| 文档版本 | v1.1 |

## 2. 建设目标

本项目实现一个移动端新闻资讯应用，覆盖新闻浏览、收藏、浏览历史、用户登录注册、个人资料、设置和 AI 问答界面。

首版目标：

1. 11 个页面均可通过 Vue Router 正常进入和返回。
2. 首页分类和新闻数据全部来自后端接口，不写死新闻内容。
3. 用户登录后可以收藏新闻、查看收藏、记录浏览历史并修改个人资料。
4. 未登录用户可以浏览新闻；访问收藏、历史和个人资料时引导登录。
5. 移动端布局与给定截图保持一致，适配常见手机宽度和安全区。
6. 所有页面具备加载、空数据、失败重试和操作反馈状态。
7. AI API Key 不写入 Git 跟踪文件；本地开发通过环境变量注入，直连模式的风险在文档中明确说明。

不在首版范围内：

- 新闻搜索、评论、点赞、分享和推送。
- 消息通知、站内信及其详情页。
- 后台管理、新闻发布和内容审核。
- 本地文件上传。后端当前只接受头像 URL。
- 找回密码、短信验证码和第三方登录。
- AI 对话历史持久化和多会话管理。

## 3. 技术栈

| 技术 | 版本建议 | 用途 |
| --- | --- | --- |
| Vue 3 | 3.x | 页面和组件，统一使用 Composition API + `<script setup>` |
| Vite | 最新稳定版 | 开发服务器、构建和 `/api` 代理 |
| Pinia | 2.x/3.x 当前稳定版 | 用户、新闻、收藏、历史状态管理 |
| Vant 4 | 4.x | 移动端 UI、表单、列表、弹层和反馈组件 |
| Vue Router | 4.x | 页面路由、鉴权守卫和导航状态 |
| Axios | 1.x | HTTP 请求、鉴权头和统一错误处理 |

依赖安装目标：

```bash
npm create vite@latest toutiao_frontend -- --template vue
cd toutiao_frontend
npm install vue-router pinia axios vant
```

首版直接全量引入 Vant 样式，避免额外增加按需加载插件和构建复杂度。后续优化包体积时再切换为按需引入。

职责约束：

- `router/` 统一维护 11 个路由、页面标题、TabBar 显示规则和登录守卫。
- 页面样式使用 `<style scoped>`；全局主题变量放在 `App.vue` 的非 scoped 样式中。

### 5.2 路由元信息

```js
meta: {
  title: '我的收藏',
  requiresAuth: true,
  showTabBar: false,
  activeTab: ''
}
```

规则：

- `requiresAuth: true` 的路由在进入前检查用户登录态。
- 未登录访问受保护页面时跳转 `/login?redirect=<原地址>`。
- 登录成功后优先返回 `redirect`，没有 `redirect` 时进入 `/my`。
- `showTabBar: true` 的页面只有首页、分类页、AI 问答和我的页面。
- 分类页的 `activeTab` 为 `home`，截图中的底部“首页”保持蓝色。
- 路由切换后默认回到页面顶部；从详情页返回列表页时可保留浏览器滚动位置。

### 6.3 主题设置（前端实现）

主题设置完全在前端完成，不调用后端接口。

支持三种模式：

| 值 | 展示名称 | 行为 |
| --- | --- | --- |
| `light` | 浅色 | 固定使用浅色主题 |
| `dark` | 深色 | 固定使用深色主题 |
| `system` | 跟随系统 | 监听 `prefers-color-scheme`，随系统切换 |

实现方式：

- 在 `App.vue` 外层使用 Vant `ConfigProvider`，传入解析后的 `light` 或 `dark`。
- 持久化键统一为 `toutiao_theme`，默认值为 `system`。
- 应用启动时先读取本地主题，再挂载页面，避免主题闪烁。
- `system` 模式下监听 `window.matchMedia('(prefers-color-scheme: dark)')`。
- 设置页点击“主题定制”打开 Vant `ActionSheet`，选择后立即生效并写入 `localStorage`。
- 不发送任何主题请求，也不产生后端数据。

深色主题自定义变量：

| 用途 | 深色值 |
| --- | --- |
| 页面背景 | `#0f1115` |
| 卡片/内容背景 | `#1a1d22` |
| 主要文字 | `#f5f6f8` |
| 次要文字 | `#a7abb3` |
| 分隔线 | `#2b2f36` |
| 主色 | `#1989fa` |
| 危险/删除 | `#ff4d4f` |

```css
:root[data-theme='dark'] {
  --app-bg: #0f1115;
  --app-surface: #1a1d22;
  --app-text: #f5f6f8;
  --app-text-secondary: #a7abb3;
  --app-border: #2b2f36;
}
```

主题切换只修改根节点变量和 Vant `ConfigProvider` 状态，不刷新页面。

## 7. 公共组件设计

### 7.1 `TabBar.vue`

底部固定导航，三个入口：

| 顺序 | 文案 | 图标 | 路由 | key |
| --- | --- | --- | --- | --- |
| 1 | 首页 | `home-o` | `/` | `home` |
| 2 | AI问答 | `chat-o` | `/ai-chat` | `ai` |
| 3 | 我的 | `user-o` | `/my` | `my` |

实现规范：

- 使用 Vant `Tabbar` 和 `TabbarItem`。
- 固定定位在页面底部，`z-index: 100`。
- 激活颜色 `#1989fa`，默认颜色 `#1f2329`。
- 高度约 `50px`，叠加 `env(safe-area-inset-bottom)`。
- 当前激活项由路由 `meta.activeTab` 决定，不直接依赖路径字符串。
- 分类页也显示 TabBar，但激活“首页”。
- 新闻详情、登录、注册、收藏、历史、个人信息和设置页不显示 TabBar。

### 7.2 `NewsItem.vue`

用于首页新闻列表和相关推荐，避免每个页面重复写新闻卡片。

Props 建议：

```js
{
  news: Object,
  compact: Boolean
}
```

标准列表布局：

```text
标题（最多 2 行）                      缩略图
简介（最多 2 行）                      80×60
作者    浏览量
```

显示规则：

- `title` 最多两行，超出省略。
- `description` 最多两行，超出省略。
- 图片位于右侧，约 `80px × 60px`，使用 `object-fit: cover`。
- 无图片时文字占满整行，不显示空白图片占位。
- 图片加载失败时显示浅灰背景和 Vant 图片失败图标。
- 元信息显示 `author || '未知作者'` 和 `views` 阅读量。
- 点击整个条目触发 `click` 事件，由父组件导航到 `/news/:id`。
- `compact: true` 时用于相关推荐：图片在左，标题单行或双行省略，不显示简介。
- 不把收藏/历史专用删除按钮放入 `NewsItem`，避免组件出现过多条件分支。

## 8. Pinia 状态设计

### 8.1 `store/user.js`

职责：登录态、当前用户资料、资料更新和密码修改。

State：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `token` | string | 从 `localStorage` 恢复 |
| `userInfo` | object/null | 当前用户信息 |
| `initialized` | boolean | 是否完成首次登录态校验 |
| `loading` | boolean | 用户信息请求状态 |

Getters：

- `isLoggedIn`：`Boolean(token)`。
- `displayName`：`nickname || username || '未登录'`。
- `avatar`：`userInfo.avatar`，为空时使用默认猫头像。

Actions：

| 方法 | 接口 | 说明 |
| --- | --- | --- |
| `login(payload)` | `POST /api/user/login` | 保存 token 和 userInfo |
| `register(payload)` | `POST /api/user/register` | 注册成功后直接登录 |
| `fetchUserInfo()` | `GET /api/user/info` | 刷新本地用户信息 |
| `updateProfile(payload)` | `PUT /api/user/update` | 更新昵称、头像、性别或简介 |
| `updatePassword(payload)` | `PUT /api/user/password` | 修改密码 |
| `logout()` | 无后端接口 | 清空 token、用户数据、收藏和历史状态 |

持久化规则：

- token 存储键统一为 `toutiao_token`。
- 页面刷新时先读取 token，再调用 `/api/user/info` 校验是否有效。
- 401 时立即清除 token 和用户状态，并跳转登录页。
- 退出登录没有后端接口，只清理客户端状态。

### 8.2 `store/modules/news.js`

职责：分类、新闻列表、分页、详情和相关推荐。

State：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `categories` | array | 后端分类列表 |
| `activeCategoryId` | number/null | 当前分类 ID |
| `list` | array | 当前分类新闻列表 |
| `page` | number | 已加载页码 |
| `pageSize` | number | 默认 10 |
| `total` | number | 当前分类总数 |
| `hasMore` | boolean | 是否还有下一页 |
| `loading` | boolean | 列表请求状态 |
| `detail` | object/null | 当前新闻详情 |
| `detailLoading` | boolean | 详情加载状态 |

Actions：

- `fetchCategories()`：获取分类并按 `sortOrder` 排序。
- `selectCategory(categoryId)`：切换分类，清空列表并重新请求第一页。
- `fetchNews({ reset })`：加载新闻分页。
- `fetchNewsDetail(id)`：加载新闻详情，同时保存 `relatedNews`。
- `clearDetail()`：离开详情页时清理当前详情。

分类缓存建议：

- 首页初次进入只请求一次分类。
- 切换分类时重置列表和页码。
- 返回首页时保留上一次 `activeCategoryId`。
- 如果 URL 带 `categoryId`，优先使用 URL 中的分类。

### 8.3 `store/modules/favorite.js`

职责：收藏列表、收藏状态和收藏写操作。

State：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `list` | array | 收藏列表 |
| `page` | number | 当前页 |
| `pageSize` | number | 默认 10 |
| `total` | number | 收藏总数 |
| `hasMore` | boolean | 是否还有下一页 |
| `loading` | boolean | 列表加载状态 |
| `statusMap` | object | `newsId -> isFavorite` 的页面内状态 |

Actions：

- `fetchList({ reset })`：分页获取收藏。
- `checkStatus(newsId)`：查询单条新闻收藏状态。
- `addFavorite(newsId)`：收藏，成功后更新 `statusMap`。
- `removeFavorite(newsId)`：取消收藏，成功后更新列表和状态。
- `clearFavorites()`：清空收藏并重置列表。
- `reset()`：退出登录时清理数据。

字段规则：

- 收藏列表项 `id` 是收藏记录 ID。
- 收藏列表项 `newsId` 才是新闻 ID。
- 点击收藏条目跳转详情必须使用 `newsId`。
- 取消收藏也必须传 `newsId`。

### 8.4 `store/modules/history.js`

职责：浏览历史列表和删除操作。

State：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `list` | array | 历史列表 |
| `page` | number | 当前页 |
| `pageSize` | number | 默认 10 |
| `total` | number | 历史总数 |
| `hasMore` | boolean | 是否还有下一页 |
| `loading` | boolean | 列表加载状态 |

Actions：

- `fetchList({ reset })`：分页获取历史。
- `addHistory(newsId)`：详情页浏览后写入历史。
- `removeHistory(historyId)`：删除单条历史记录。
- `clearHistory()`：清空全部历史。
- `reset()`：退出登录时清理数据。

字段规则：

- 历史列表项 `id` 是浏览记录 ID，用于 `DELETE /api/history/delete/{id}`。
- 历史列表项 `newsId` 是新闻 ID，用于跳转详情。
- 新增历史成功后应使本地列表失效，下次进入历史页重新加载。

### 8.5 AI 对话状态

`store/` 下不新增 AI 模块。对话消息保存在 `AIChat.vue` 的组件内，并通过 `config/api.js` 导出的 `sendAiChat()` 发起请求。

```js
messages = [
  { role: 'assistant', content: '你好！我是AI助手，有什么可以帮助你的吗？' }
]
```

原因：AI 接口直接调用第三方大模型服务，不经过新闻后端，也没有多会话持久化需求。刷新页面后消息清空。

## 9. API 层设计

### 9.1 基础配置

开发环境通过 Vite 代理访问 FastAPI：

```js
// vite.config.js
server: {
  proxy: {
    '/api': {
      target: 'http://127.0.0.1:8000',
      changeOrigin: true
    }
  }
}
```

`config/api.js` 负责：

- 创建 Axios 实例。
- 设置 `baseURL`、超时时间。
- 自动附加 token。
- 统一解包 `{ code, message, data }`。
- 统一处理 401、404、422 和网络异常。
- 导出用户、新闻、收藏、历史接口函数。
- 配置 DeepSeek AI 地址、模型和本地环境变量中的 API Key。
- 导出 `sendAiChat(messages)`，页面不直接拼接第三方请求。

建议配置：

```js
export const apiConfig = {
  baseURL: import.meta.env.VITE_API_BASE_URL || '/api'
}

export const aiChatConfig = {
  apiEndpoint: 'https://api.deepseek.com/chat/completions',
  apiKey: import.meta.env.VITE_AI_API_KEY || '',
  model: 'deepseek-flash'
}
```

配置约束：

- `vite.config.js` 将 `/api` 代理到 `http://127.0.0.1:8000`。
- Axios 的 `baseURL` 使用 `/api`，这样请求会经过 Vite 代理。
- 如果把 `http://127.0.0.1:8000` 直接作为 Axios 的 `baseURL`，浏览器会发起跨域请求，需要后端额外配置 CORS；当前设计不采用该方式。
- `VITE_AI_API_KEY` 只来自本地环境变量或部署环境，不写入源码、文档或 Git。
- 任何曾出现在公开日志、聊天或代码中的 Key 都应立即吊销并重新生成。

AI 请求格式采用 OpenAI 兼容接口：

```http
POST https://api.deepseek.com/chat/completions
Authorization: Bearer <VITE_AI_API_KEY>
Content-Type: application/json
```

```json
{
  "model": "deepseek-flash",
  "messages": [
    {
      "role": "system",
      "content": "你是新闻资讯助手，请使用简洁中文回答问题。"
    },
    {
      "role": "user",
      "content": "今天有哪些科技新闻？"
    }
  ],
  "stream": false
}
```

响应内容从 `choices[0].message.content` 读取。

调用约束：

- AI 请求使用独立的 Axios 实例，不附加新闻后端的 `Authorization` token。
- 建议超时时间为 `60s`。
- 首版不使用流式输出。
- 前端直连第三方接口时 API Key 会出现在浏览器运行环境和网络请求中，仅适用于本地开发或明确接受该风险的项目。生产环境建议改为后端代理。
- 如果 DeepSeek 域名被浏览器 CORS 拦截，必须通过后端代理，不能在客户端绕过。

### 9.2 认证请求头

后端要求原始 token，不加 `Bearer`：

```http
Authorization: <token>
```

Axios 请求拦截器规则：

```js
const token = localStorage.getItem('toutiao_token')
if (token) {
  config.headers.Authorization = token
}
```

禁止在单个页面手动拼接鉴权头。

### 9.3 响应处理

后端统一响应结构：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

Axios 响应拦截器建议直接返回 `response.data.data`，业务失败时抛出带 `message` 的错误，由页面或 store 显示 Toast。

处理规则：

| HTTP 状态 | 前端行为 |
| --- | --- |
| 200 | 返回业务数据 |
| 400 | 显示后端 `message`，例如“用户名已存在” |
| 401 | 清理登录态，跳转 `/login` |
| 404 | 显示“内容不存在”或页面错误态 |
| 422 | 显示“请求参数校验失败” |
| 500 | 显示“服务器内部错误，请稍后重试” |
| 网络错误/超时 | 显示“网络异常，请检查连接后重试” |

## 10. 页面详细设计

### 10.1 首页 `Home.vue`

路由：`/`

页面目标：展示当前分类的新闻信息流。

布局：

1. 顶部白色导航栏，居中标题“新闻资讯”。

数据来源：

- 分类：`GET /api/news/categories?limit=100`
- 新闻：`GET /api/news/list?categoryId=<id>&page=<page>&pageSize=10`

交互：

- 初次进入请求分类，默认选中第一个分类“头条”。

- 标题最多两行，简介最多两行，图片靠右。

### 10.3 AI 问答 `AIChat.vue`

路由：`/ai-chat`

页面目标：调用配置中的 DeepSeek 大模型接口，完成移动端对话。

布局：

1. 顶部标题“AI问答”。
2. 可滚动消息区。
3. 底部固定在 TabBar 上方的输入栏和“发送”按钮。
4. TabBar 激活“AI问答”。

本地初始消息：

```text
你好！我是AI助手，有什么可以帮助你的吗？
```

交互：

- 用户输入非空内容后点击“发送”或按回车发送。
- 用户消息右对齐，AI 消息左对齐。
- 消息发送后清空输入框，滚动到消息底部。
- 输入为空时禁用发送。

- 请求失败时显示错误气泡和“重试”操作，不伪造模型回复。

状态：

- 初始：一条欢迎消息。
- 发送中：用户气泡立即出现，助手气泡显示“正在思考...”。
- 失败：助手气泡显示失败提示，并提供重试。
- 键盘弹出：输入栏位于可视区域底部，不被软键盘遮挡。
- 消息仅保存在当前组件内，刷新页面后清空。

调用链路：

```text
用户发送
-> 组装 system + 历史消息
-> config/api.js: sendAiChat()
-> POST https://api.deepseek.com/chat/completions
-> 读取 choices[0].message.content
-> 插入 assistant 气泡
```

安全约束：

- Key 从 `VITE_AI_API_KEY` 读取，不写入 Git 跟踪文件。
- AI 请求不得携带新闻系统的登录 token。
- 当前前端直连模式下 Key 会暴露给浏览器，属于已知风险；泄漏后必须立即轮换。
- 生产部署优先改为后端代理，前端只调用自己的 `/api/ai/chat`。
- AI 请求超时、限流或 CORS 失败时，显示可重试错误，不自动无限重试。

## 11. 跨页面业务流程

### 11.1 未登录浏览新闻

```text
打开首页
-> 获取分类
-> 默认选中头条
-> 获取新闻第一页
-> 点击新闻
-> 获取新闻详情
-> 展示正文和相关推荐
```

未登录访问详情时不请求收藏状态，不写浏览历史。

### 11.2 登录流程

```text
点击“去登录”或受保护入口
-> 记录 redirect
-> 输入用户名和密码
-> POST /api/user/login
-> 保存 token + userInfo
-> 清理旧搜索/筛选状态
-> 跳转 redirect 或 /my
```

### 11.3 注册流程

```text
进入注册页
-> 输入用户名、密码、确认密码
-> 前端校验两次密码一致
-> POST /api/user/register
-> 保存 token + userInfo
-> 跳转 /my
```

### 11.4 收藏流程

```text
详情页
-> 已登录则查询收藏状态
-> 点击星标
-> 未收藏：POST /api/favorite/add
-> 已收藏：DELETE /api/favorite/remove?newsId=...
-> 更新星标和收藏列表状态
```

### 11.5 浏览历史流程

```text
登录后进入详情页
-> 详情请求成功
-> POST /api/history/add
-> 历史列表缓存失效
-> 下次进入历史页重新 GET /api/history/list
```

同一条新闻多次浏览会产生多条历史记录，前端不在当前后端能力下自行去重。

### 11.6 收藏/历史进入详情

```text
收藏列表项.newsId -> /news/<newsId>
历史列表项.newsId -> /news/<newsId>
```

删除历史记录使用 `history.id`，不能使用 `newsId`。

### 11.7 退出登录

退出入口位于设置页，仅登录后显示。

```text
点击设置页的“退出登录”
-> 清除 localStorage 中的 token
-> 清空 userInfo
-> 清空收藏和历史 store
-> 返回 /my
```

### 11.8 AI 问答

```text
进入 AI 问答
-> 展示欢迎消息
-> 输入内容
-> sendAiChat() 提交模型、系统提示词和对话历史
-> 读取 choices[0].message.content
-> 展示 assistant 消息
-> 请求失败时显示错误和重试
-> 刷新页面后消息清空
```

主题流程：

```text
设置页选择浅色/深色/跟随系统
-> 更新 App.vue 的 ConfigProvider
-> 更新根节点 data-theme
-> 写入 localStorage
-> 不请求后端
```

## 12. 登录守卫与权限规则

需要登录的页面：

- `/favorites`
- `/history`
- `/profile`

公共页面：

- `/`
- `/category`
- `/ai-chat`
- `/my`
- `/news/:id`
- `/login`
- `/register`
- `/settings`

守卫逻辑：

```js
if (to.meta.requiresAuth && !userStore.isLoggedIn) {
  return {
    path: '/login',
    query: { redirect: to.fullPath }
  }
}
```

补充规则：

- 已登录访问 `/login` 或 `/register`，直接跳转 `/my`。
- token 存在但 `/api/user/info` 返回 401 时，视为未登录。
- 401 后不保留受保护页面的旧数据。
- 退出登录后如果当前在受保护页面，立即跳转 `/my`。

## 13. 数据格式与展示规则

### 13.1 时间

- 新闻发布时间：`YYYY-MM-DD HH:mm`
- 收藏时间：`YYYY-MM-DD HH:mm:ss`
- 浏览时间：`YYYY-MM-DD HH:mm:ss`
- 后端返回 ISO 字符串时，前端统一转换为本地展示格式。
- 无效时间显示 `--`，不显示 `Invalid Date`。

### 13.2 浏览量

- 与截图保持一致，显示原始浏览量和“阅读”。
- 示例：`12619 阅读`。
- 不擅自改成“1.2 万阅读”，除非后续统一数据展示规范。

### 13.3 文本省略

- 首页标题最多 2 行。
- 首页简介最多 2 行。
- 收藏/历史标题最多 2 行。
- 相关推荐标题最多 2 行。
- 所有省略必须保留可点击入口，不显示半截文字。

### 13.4 图片

- 无图片：隐藏图片区域，文字占满宽度。
- 加载失败：显示浅灰占位和图片图标。
- 头像失败：显示默认猫头像。
- 图片不参与业务判断，不影响新闻详情加载。

## 14. 交互状态规范

每个请求页面至少包含以下状态：

| 状态 | 要求 |
| --- | --- |
| 初始加载 | 骨架屏或加载提示 |
| 请求成功且有数据 | 正常列表/详情 |
| 请求成功但无数据 | 空状态和下一步入口 |
| 请求失败 | 错误文案和重试按钮 |
| 分页加载 | 底部 loading |
| 没有更多 | 底部提示 |
| 操作中 | 按钮 loading/disabled |
| 操作成功 | Toast 或页面状态更新 |
| 操作失败 | 保留原状态并提示错误 |

防重复规则：

- 登录、注册、收藏、删除、清空、修改资料和修改密码在请求中禁止重复提交。
- 收藏操作要防止连续点击导致重复请求。
- 列表请求要防止同一分类重复加载同一页。

## 15. 功能边界与技术约束

| 功能 | 当前方案 | 首版处理 |
| --- | --- | --- |
| AI 问答 | DeepSeek OpenAI 兼容接口 | 前端通过 `config/api.js` 直接调用，不经过新闻后端 |
| 消息通知 | 暂不开发 | 删除“消息通知”入口，不新增消息页面 |
| 通知设置 | 暂不开发 | 从设置页移除 |
| 主题定制 | 前端状态 + CSS 变量 | 支持浅色、深色、跟随系统，并持久化到 `localStorage` |
| 语言设置 | 无多语言资源 | 设置页占位，默认中文 |
| 隐私设置 | 无设置接口 | 设置页占位 |
| 头像文件上传 | 后端只接受头像 URL | 首版只支持 URL 或默认头像 |
| 退出登录接口 | 后端无 logout 接口 | 前端清理本地 token |
| 找回密码 | 后端无接口 | 不展示入口 |
| 评论/点赞/分享 | 后端无接口 | 不实现 |
| 搜索 | 后端无搜索接口 | 不实现，避免做无效搜索框 |

AI 技术约束：

1. 端点固定为 `https://api.deepseek.com/chat/completions`，模型由 `aiChatConfig.model` 配置。
2. Key 从 `VITE_AI_API_KEY` 读取，不写入文档、源码或 Git。
3. 前端直连会暴露 Key，当前仅按开发环境方案设计；生产建议改为后端代理。
4. 不把新闻系统的登录 token 发送给 AI 服务。
5. 对话只保存在当前页面内，不写入数据库，也不跨刷新保留。
